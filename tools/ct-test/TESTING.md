# CreatorToolkit — как тестировать в игре (ct-test)

Инструмент и шпаргалка для живых проверок мода в Slime Rancher 2 без ручного «натыкивания»:
команды в игру идут через `cmd.txt`, ответы — строкой `CtTest` в `status.txt` и файлами-дампами,
скриншоты снимает сам мод, а защищённые сохранения сверяются по SHA-256 до и после сессии.

- Скрипт: `tools\ct-test\ct.ps1` (только ASCII, PowerShell 5.1).
- Сценарии: `tools\ct-test\scenarios\*.txt`.
- Результаты: `_work\ct-test\` (логи сценариев, `shots\*.png`, копии дампов, `baseline.json`).
- Резервные копии сохранений: `backup\ct-saves-<дата>`.
- Внутриигровая часть: `src\creator\M28TestIpc.cs` (команды `ct-*`, `m28-*`) и `M28TestPolicy` в `M28Policy.cs`.

## Правила безопасности (обязательные)

1. Тестируем **только** на тестовом сохранении `20261020001829_6` (`M26AcceptanceCore.TestGameName`).
   Основное сохранение `20261013155400_5` и любые другие не загружаем.
2. Команды `ct-*` / `m28-*` мод выполняет только пока существует файл
   `UserData\CreatorToolkit\ct-test.enabled` (перечитывается при каждой команде). Без него ответ —
   `ignored: opt-in file ct-test.enabled missing`. Файл создаёт `ct.ps1 prep`, удаляет `ct.ps1 finish`.
3. Всё, что меняет сохранение (`m28-unlock`, `m28-confirm`, `m28-custom-add`, `m28-custom-del`),
   проверяет, что загружено тестовое сохранение; иначе — отказ. `m28-confirm` принимает окно
   подтверждения только при точном совпадении заголовка.
4. В игру входим только через `ct-continue-test` (`ct.ps1 continue`): он сам проходит стартовый экран
   и загружает игру лишь когда «Продолжить» ведёт в тестовое сохранение. Обычную команду `continue`
   не использовать — она загрузит любое последнее сохранение.
5. Процесс игры не убиваем. Выход — `ct.ps1 quit` (мод сохраняет и выходит; скрипт откажется,
   если загружено не тестовое сохранение).
6. `prep`/`launch` отказываются работать при запущенной игре; DLL ставится только при закрытой игре
   и только после зелёных тестов (`src\creator\test.ps1`).
7. Для агента: перед запуском или закрытием игры — запись в блокнот пользователя; если игрой
   пользуется человек (окно в фокусе, персонаж двигается) — не вмешиваться и спросить.
8. После сессии — `ct.ps1 finish`: opt-in удалены, все защищённые `*.sav` совпали с отпечатками
   (`PROTECTED SAVES ... bad=0`), ошибок в `MelonLoader\Latest.log` нет.

## Быстрый старт

```bat
cd /d C:\path\to\SR2-CreatorToolkit   :: корень репозитория; папку игры можно задать через SR2_GAME_DIR
set CT=powershell -NoProfile -ExecutionPolicy Bypass -File tools\ct-test\ct.ps1
%CT% prep              :: игра закрыта: копия сохранений, отпечатки, установка DLL, ct-test.enabled
%CT% launch            :: запуск и ожидание главного меню
%CT% continue          :: вход в тестовое сохранение (повторяет шаги стартового экрана сам)
%CT% run m28-smoke     :: сценарий -> _work\ct-test\m28-smoke.log + скриншоты
%CT% quit              :: сохранить и выйти (только тестовое сохранение)
%CT% finish            :: убрать opt-in, сверить защищённые сохранения, проверить лог
```

Длинный сценарий в фоне (вызов из MCP/cmd не ждёт его окончания):

```bat
del /q _work\ct-test\m28-drone.done 2>nul
start "" /b powershell -NoProfile -ExecutionPolicy Bypass -File tools\ct-test\ct.ps1 run m28-drone > nul 2>&1
:: затем ждать появления _work\ct-test\m28-drone.done и читать m28-drone.log
```

## Операции ct.ps1

| Операция | Что делает |
|---|---|
| `help` | краткая справка |
| `prep [-NoInstall] [-M27]` | при закрытой игре: копия всей папки сохранений с проверкой хэшей, `baseline.json` (все `*.sav`, кроме тестового), установка DLL через `src\creator\install.ps1`, файл `ct-test.enabled` (с `-M27` ещё `m27-acceptance.enabled` для старых команд `m27-*`) |
| `launch` | запуск игры штатным лаунчером (`src\creator\dispatch.ps1`) и ожидание главного меню |
| `continue` | `ct-continue-test` до загрузки тестового сохранения, затем ожидание `Ready` |
| `menu` / `ready` | ждать главное меню / готовность геймплея (`-TimeoutSec`, по умолчанию 180) |
| `cmd <строка> [...]` | отправить строки команд; для `ct-`/`m28-` печатает новый результат `CtTest`. **Каждый аргумент — отдельная команда**, поэтому команду с параметрами берите в кавычки: `cmd "m28-drone mode auto"` |
| `status [ключ...] [-Pattern re]` | значения из `status.txt` (по умолчанию Ready, GameplayScene, SceneLoading, SaveGameName, CtTest) |
| `shot <имя>` | скриншот кадра игры (вместе с IMGUI) → `_work\ct-test\shots\<имя>.png` |
| `show <файл> [строк]` | показать и скопировать файл из `UserData\CreatorToolkit` (дампы команд) |
| `run <сценарий>` | выполнить `scenarios\<сценарий>.txt` → `_work\ct-test\<сценарий>.log` и `.done`; код выхода 3 при FAIL |
| `click <x> <y>` / `key <vk> [мс]` | настоящий клик/клавиша в окно SR2 (через `src\creator\desktop-task.ps1`), пиксели окна от левого верхнего угла |
| `log [n] [-Pattern re]` | счётчики ошибок/предупреждений `Latest.log` и последние строки `CT test`, `[M28]`, ошибки |
| `quit` / `wait-exit` | сохранить и выйти через мод / дождаться завершения процесса |
| `hashes` | сверить защищённые сохранения с `baseline.json` (ничего не меняет) |
| `finish` | при закрытой игре: удалить opt-in, сверить сохранения, проверить лог, показать хэш DLL; код 2 при расхождении |

Переменные окружения (если пути другие): `SR2_GAME_DIR`, `SR2_SAVE_DIR`, `CT_TEST_SAVE`.

## Канал связи с модом

- `UserData\CreatorToolkit\cmd.txt` — строки команд. `ct.ps1` пишет `cmd.pending` и переименовывает;
  мод читает и удаляет файл (если файл не исчез за 25 с — мод не опрашивает: игра не запущена или висит).
- `status.txt` — пишется модом постоянно. Ключи для тестов: `Ready`, `GameplayScene`, `SceneLoading`,
  `SaveGameName`, `CtTest` (время + результат последней `ct-`/`m28-` команды), `M28Drone`, `M28Compass`,
  `M28Marker`, `M28Unlocks`, `M28Atlas` (последние пять — только при `ct-test.enabled`).
- `MelonLoader\Latest.log` — строки `CT test: …` (каждая команда) и `[M28] …` (события инструментов).

## Внутриигровые команды

| Команда | Результат |
|---|---|
| `ct-help` | список команд → `ct-help.txt` |
| `ct-state` | одна строка: ready, сохранение и `test=True/False`, меню, окно подтверждения, карта, панель атласа, состояние M28-инструментов |
| `ct-ui-dump <цель> [глубина]` | дерево UI → `ct-ui-<цель>.txt`; цель `map`, `drone`, `marker`, `compass`, `canvases` или `name:<часть пути>` |
| `ct-ui-hit <x> <y>` | что под точкой экрана по EventSystem (пиксели от левого верхнего угла) → `ct-ui-hit.txt`; кнопка дронов помечается `<- drone button` |
| `ct-ui-find <текст>` | активные элементы, путь которых содержит текст (+ текст TMP) → `ct-ui-find.txt` |
| `ct-continue-test` | главное меню → тестовое сохранение (см. правило 4) |
| `ct-atlas-panel expanded\|collapsed\|toggle` | развернуть/свернуть панель «Атлас создателя» на карте |
| `ct-atlas-search <текст>\|clear` | M29: поиск атласа, как поле на странице атласа (UTF-8 можно как %XX: `%D0%B4%D1%80%D0%BE%D0%BD` = «дрон»); `clear` = кнопки «×»; только до перезапуска |
| `ct-atlas-state` | M29: поиск, совпадения и свои метки на текущей карте, нарисованные метки, слот карточки, перекрыта ли выбранная метка |
| `ct-atlas-focus pod\|own\|drone\|gordo\|teleport\|<слой> [n]` | M29: выбрать и отцентровать n-й объект на открытой карте (только тестовое сохранение) |
| `ct-ghost-state` | M29: зона каждого маршрута фантомного дрона и её источник (membership/map/authored/unique/live), страница атласа, группа компаса и дистанция → `ct-ghost.txt`; только чтение |
| `ct-palette-sources` | M29: стили вакпака и все записи магазина / киоска наград, которые их выдают, с условиями -> `ct-palettes-src.txt`; только чтение |
| `ct-layer-audit` | M29: по каждому слою: точки, дубли, зона, в радиусе, список навигатора, компас -> `ct-layers.txt`; только чтение |
| `ct-minimap off\|radar\|terrain` | режим мини-карты, как кнопка на странице атласа (M29: сохраняется в `navigation.cfg`) |
| `ct-nav state\|set <ключ> <значение>\|reset\|zoom in\|out\|reload` | M29: настройки мини-карты и компаса, как страница «Карта → Навигация»; ключи `minimap` (off/terrain/radar), `minimap.size` (small/medium/large), `minimap.range` (30–300), `minimap.corner` (top-right/top-left/bottom-right/bottom-left), `minimap.transparency` (0–100 %, шаг 5), `minimap.orientation` (heading/north), `compass` (on/off), `compass.range` (50–1000 м, шаг 25), `compass.markers` (1–16), `compass.ghosts` (normal/high/pinned). Пишется в `UserData\CreatorToolkit\navigation.cfg` через ~1 с (атомарно); `reset` — вид и пределы по умолчанию; `reload` — перечитать файл |
| `ct-menu <вкладка> [раздел]` | открыть меню мода на вкладке (4 = разблокировки: раздел 0 — карточки, 1 — трекинг) |
| `m28-drone state\|find\|mode <auto\|below\|left\|off>\|climb <n\|auto>\|pick <i>` | штатная кнопка меню дронов: состояние, отчёт о поиске (`m28-drone.txt`), режим переноса |
| `m28-compass-dump` | экземпляры компаса и наши метки → `m28-compass.txt` |
| `m28-compass-style overlay\|replace\|off` | как наши метки получают иконку на компасе |
| `m28-palettes` | список стилей вакпака (только чтение) → `m28-palettes.txt` |
| `m28-unlock palettes\|styles\|blueprints` | открыть окно подтверждения разблокировки (тестовое сохранение) |
| `m28-confirm palettes\|styles\|blueprints` | принять его, если заголовок совпал (тестовое сохранение) |
| `m28-player-marker state\|capture\|dump\|forget` | копия штатной метки игрока для мини-карты; `dump` → `m28-player-marker.txt` |
| `m28-custom-add <цвет 0-5> [имя]` | своя метка у игрока (тестовое сохранение; хранится в `waypoints-<сейв>.json`, не в сейве игры) |
| `m28-custom-goal <id\|last>` / `m28-custom-del <id\|last>` | сделать целью компаса / удалить |
| `m28-tracking` | обновляет трекинг и пишет сводку капсул/гордо по состояниям и «не загружался» по зонам → `m28-tracking.txt` |

Полезные старые команды: `atlas` (открыть карту с атласом), `atlas-close`, `close` (закрыть меню мода),
`menu`, `menu-sources` (меню мода со слоями «Горшочки» и «Спавнеры»), `capture` (скриншот, его вызывает `ct.ps1 shot`), `quit`.
Страница «Навигация» для скриншота: `m27-explorer 4` (нужен `m27-acceptance.enabled`, то есть `prep -M27`).

## Сценарии

Одна строка — один шаг, `#` — комментарий:

| Шаг | Значение |
|---|---|
| `cmd <строка>` | отправить команду (для `ct-`/`m28-` дождаться `CtTest`) |
| `sleep <сек>` | пауза (дробные секунды можно) |
| `shot <имя>` | скриншот |
| `show <файл> [строк]` | вывести дамп в лог сценария |
| `status <ключ...>` | значения из `status.txt` |
| `expect <ключ> <regex>` | PASS/FAIL по значению из `status.txt` |
| `expect-ct <regex>` | PASS/FAIL по результату последней `cmd` |
| `expect-file <файл> <regex>` | PASS/FAIL по содержимому дампа |
| `ready` / `menu` / `continue` | ожидания (при таймауте сценарий прерывается) |
| `click <x> <y>` / `key <vk> [мс]` | настоящий ввод в окно игры |
| `log [n] [regex]` | строки из `Latest.log` |

Готовые сценарии:

- `m28-smoke` — только чтение: состояние, дампы всех M28-инструментов, скриншот HUD.
- `m28-drone` — карта: кнопка меню дронов не под кнопкой «−» атласа (в развёрнутом и свёрнутом виде), дампы и скриншоты.
- `m28-marker` — копия метки Беатрикс с полной карты и её вид на мини-карте.
- `m28-compass` — реальные иконки на компасе, своя метка с флажком (метка добавляется и удаляется).
- `m28-unlock` — **меняет тестовое сохранение**: открывает все стили вакпака.
- `m28-tracking` — трекинг капсул/гордо: «не загружался» вместо «состояние неизвестно».

## Чек-лист M28

1. **Кнопка дронов.** `m28-drone state` — `moved` (опущена под шапку атласа) или `clear`; `ct-ui-hit 1850 62`
   (центр «−» при 1920×1440, в общем случае `(sw−54s, 48s)`, `s = clamp(sh/1080, 0.6, 1.3)`) не содержит
   `<- drone button`; настоящий `click` по «−» сворачивает атлас и не открывает панель дронов.
2. **Компас.** `m28-compass-dump`: у штатных точек иконки вместо звёзд, у своих меток — флажок в их цвете.
3. **Стили вакпака.** `m28-palettes` показывает, сколько закрыто; после `m28-unlock palettes` +
   `m28-confirm palettes` закрытых 0, стили видны в штатном меню вакпака.
4. **Метка Беатрикс.** После открытия карты `M28Marker: parts>0`; на мини-карте портрет в тёмном кольце,
   хвост-указатель и зелёный конус обзора, конус поворачивается с камерой; до первой копии — стрелка `↑`.
5. **Трекинг.** Капсулы из ни разу не загружавшихся участков — «Не открыта · участок ещё не загружался».

## Чек-лист M29 · навигация (задачи 4–5)

1. **Настройки.** `ct-nav state` — путь к `navigation.cfg`, `exists=False` до первого изменения; после
   `ct-nav set minimap terrain`, `ct-nav set minimap.corner bottom-left`, `ct-nav set minimap.size large` через ~1 с
   `saves=1` и файл создан; `ct-nav zoom in|out` — плавный масштаб (30–300 м).
2. **Перезапуск.** `quit` → `launch` → `continue`: `ct-nav state` — «загружено из navigation.cfg · ключей 11»,
   мини-карта сразу в сохранённом углу; `m28-player-marker state` — «3 частей загружено» без открытия карты.
3. **Компас.** `ct-nav set compass.range 400`, `compass.markers 10`, `compass.ghosts pinned` → `ct-layer-audit`:
   компас 10 из 10, starved 0; ближайший фантомный дрон зоны с наградой всегда на компасе.
4. **Источники.** `menu-sources` + `close` → «Горшочки» и «Спавнеры» в списке, на мини-карте и на компасе
   (`ct-layer-audit`: noGroup 0).
5. **Уборка.** После теста закрыть игру и удалить `navigation.cfg` — вернутся умолчания (мини-карта выкл.,
   средняя, 90 м, справа сверху; компас 250 м, 6 меток).

## Как добавить новую тестовую команду

1. `src\creator\M28Policy.cs` → `M28TestPolicy.Help`: строка с синтаксисом.
2. `src\creator\M28TestIpc.cs` → `Handle`: `case "ct-…": return Run(app,a[0],()=>…);`.
   Если команда меняет сохранение — первой строкой `M26AcceptanceCore.RequireTestSave(app);`.
3. `src\creator\tests\M28Regression.cs` → массив `Commands`: офлайн-тест проверит, что команда
   обработана и описана в `ct-help`.
4. `src\creator\build.ps1` (0 warnings / 0 errors), `src\creator\test.ps1`, затем `ct.ps1 prep`.

Заметки разработчику: `GUI.DrawTextureWithTexCoords` в этой сборке игры роняет процесс — не использовать;
`GUI.BeginGroup` под поворотом `GUI.matrix` не режет — не полагаться на него;
`ImageConversion.LoadImage` падает с MissingMethodException (`ReadOnlySpan.GetPinnableReference`) — PNG читать
через `M29PngDecoder.Decode` + `SetPixels32` (как `M28PlayerMarker.Upload`).

## Частые проблемы

- `CT (no new result …)` — нет `ct-test.enabled` (запустить `prep`) или игра ещё грузится (`status`).
- `cmd.txt not consumed` — игра не запущена, зависла или стоит на системном окне.
- Мини-карта «Рельеф» тёмная и рядом плашка «рельеф: откройте карту игры в этой зоне» — рисунок атласа
  ещё не откалиброван; один раз открыть карту игры (`atlas`, затем `atlas-close`).
- `continue stopped: … continue save is '…'` — «Продолжить» ведёт в другое сохранение. Ничего не
  загружено; один раз вручную загрузить `20261020001829_6` через «Загрузить игру», затем повторить.
- `PROTECTED SAVES … bad>0` — немедленно остановиться и восстановить файл из `backup\ct-saves-<дата>`
  (путь печатает `finish`).
- Игрой пользуется человек (`status Focused PlayerMove Position`: окно в фокусе, позиция
  меняется) — ничего, что меняет экран или сохранение (`atlas`, `ct-menu`, `m28-unlock`, `click`,
  `key`, `quit`). Можно только читать: `status`, `hashes`, `log`, `m28-compass-dump`,
  `m28-palettes`, `m28-player-marker state`, `m28-tracking`, `ct-state`.
- `m28-tracking` в сборках до 73facffe… даёт `rows=0`, пока не открыта страница трекинга;
  там же старая `m27-track-dump <метка>` (нужен `m27-acceptance.enabled`) сама обновляет список и
  пишет `m27-tracking-<метка>.json`.
