# Creator Toolkit 0.7.0 — Slime Rancher 2

Автономный MelonLoader / IL2CPP-мод. Отдельная `CreatorToolkit.dll` (.NET 6), без Minecraft, WebSocket, shared memory и старого моста. Целевая игра текущей сборки: Slime Rancher 2 1.3.0. Исходники: `src/creator`.

## Новое в 0.7.0: камера, FPS, имена сейвов, свободная установка

Всё выключено по умолчанию; выбор сохраняется в `UserData/CreatorToolkit/capture.cfg` и `save-names.cfg`.

- **Съёмка → «Камера и запись…»**
  - **Угол обзора (FOV)** 30–120°. Пишется после собственного обновления камеры игры и возвращается при выключении.
  - **Плавный зум**: удерживайте C / Z / V / СКМ / M4 (боковая кнопка мыши) — плавное приближение ×1,5…×8, отпустите — возврат. Не срабатывает в меню, на карте и в окнах игры.
  - **Плавная физика**: интерполяция Rigidbody у слаймов и предметов — без дрожания при FPS выше частоты физики. Выключение возвращает каждому телу исходное значение.
  - **Счётчик FPS** в выбранном углу: FPS, мс кадра и пик за секунду; виден и в главном меню.
  - **FPS в фоне** (10 / 15 / 30 / 60): когда окно игры не активно (Alt+Tab, свёрнуто) — меньше нагрузки; вернулись в игру — targetFrameRate и VSync точно те же, что были.
- **Удобство → «Имя сейва…»**: своё имя текущего сохранения (до 28 символов). В главном меню («Файлы сохранений») вместо «Файл N» показывается это имя тем же шрифтом, что и соседние подписи; длинное имя уменьшается по ширине кнопки (штатный лимит в 13 видимых символов снимается и возвращается вместе с подписью). Сами сейвы не меняются; без мода снова видны обычные подписи.
- **Спавн → Гаджеты → «Свободная установка»**: гаджеты и декорации в штатном режиме строителя ставятся без проверки пересечений и уклона, дальность 15 → 60 м. Выключение возвращает штатные правила. Это чит: в коопе — только при Allow Cheats.

Идеи — моды с Nexus Mods (код написан с нуля, ничего не скопировано): Smooth Zoom, FPS Counter, Background FPS Limiter и Name Your Save — **Damiano**; Fov Changer — **huoyan1231**; Interpolate All Rigid Bodies — **Brynzananas**; Placement Improvements — **Lunarsnail0**. Если один из этих модов установлен, не включайте ту же функцию в CT одновременно с ним.

## Кооп: Ranching Together (0.6.1)

Creator Toolkit работает вместе с мультиплеером **Ranching Together** (SR2MP, расширение Starlight). Связь только через рефлексию: без SR2MP мод ведёт себя как раньше, друзьям Creator Toolkit не нужен.

- **Правила сервера.** Читы CT (спавн, деньги, пополнение, полёт, бессмертие, скорость, телепорты, открытия, бесплатные гаджеты) работают, только если хост включил **Allow Cheats** в настройках Ranching Together и перезапустил сервер — так же, как консольные читы самого SR2MP, для хоста и гостей. Выключенные читы гасят уже включённые эффекты.
- **Время и погода** принадлежат хосту: гость их не меняет, хосту нужны читы сервера.
- **Только одиночная игра:** заморозка времени и мобов, кинематографическая скорость, ускорение симуляции, спавн гордо (нативная ловушка не синхронизируется).
- **Синхронизация спавна.** Созданные CT слаймы и предметы передаются остальным игрокам через SR2MP; лучистое сияние и настройки прототипов видны только вам. Очистка своих объектов синхронизируется.
- Интерфейс, карта, метки, радар, графика и HUD доступны всегда. Внизу меню — режим: «Кооп · хост · читы вкл» и т. п.
- SR2 Mod Manager читает метку `SR2ModManager.CompatibleWith = SR2MP;Starlight` и не показывает «конфликт хуков» для этой пары.

## Совместимость с модами (Mod Compatibility)

Creator Toolkit рассчитан на запуск рядом с другими модами MelonLoader. В MelonLoader 0.7 работает HarmonyX: префиксы всех модов выполняются всегда, префикс с `return false` отменяет только сам метод игры (и транспайлеры на нём), постфиксы выполняются всегда. CT соблюдает правила, при которых его хуки не ломают чужие:

- **Только префиксы и постфиксы**, точечно на конкретные методы — без транспайлеров, финализаторов, `PatchAll`/`UnpatchAll`.
- **Последним в очереди** (`Priority.Last`): другие моды видят ванильные аргументы и результат раньше CT. Метод игры отменяется, только пока включена соответствующая функция (бессмертие, бесконечная энергия, заморозка времени или слаймов, бесконечный инвентарь, бесконечный режим строителя).
- **Ошибки не уходят в общую цепочку.** Если хук CT упал, этот вызов идёт по ванильному пути, а чужие префиксы и постфиксы продолжают работать.
- **Самоизоляция.** Если хук сбоит 3 раза за 60 секунд, CT снимает только свой патч с этого метода (хуки бесконечного строителя снимаются вместе, режим выключается) и показывает уведомление. Чужие патчи не трогаются. Если хук встал не полностью, CT убирает свою половину.
- **Сверка хуков.** Примерно через 15 и 60 секунд после старта CT сверяет свои методы с чужими патчами и пишет в журнал MelonLoader и в диагностику строку `Coexistence: hooked=… shared=… [владельцы] foreign-transpilers=… foreign-cancels=… isolated=… install-failures=…`.
- **Метки для SR2 Mod Manager:** `SR2ModManager.HookPolicy = cooperative` (префиксы с отменой не конфликтуют с чужими префиксами и постфиксами) и `SR2ModManager.CompatibleWith = SR2MP;Starlight;InfiniteHealth`.

Проверено в SR2 Mod Manager с Ranching Together 0.3.9, Starlight 4.0.4, SlimeLive 0.5.1, Minecraft HUD 1.0.0 и Review Director 3.0.0: у всех «совместим», проблем — 0. Настоящие конфликты (чужие префиксы с отменой или транспайлеры на тех же методах) менеджер по-прежнему показывает.

### Моды с Nexus и Ranching Together (Mod Support)

CT узнаёт сторонние моды по имени из `MelonInfo` или имени сборки — без ссылок на их DLL, поэтому отсутствие или обновление чужого мода не ломает загрузку. Чужие моды CT не патчит и их код не вызывает. Найденные моды и режим лимитов вакпака пишутся в журнал MelonLoader и в диагностику строкой `Interop: mods=[…] vac-limits=vanilla|slot […]`.

| Мод | Что делает CT |
|---|---|
| Vacuum Modifications (Nexus 45), официальная поддержка в Ranching Together | «Заполнить» и автопополнение берут лимит слота (`AmmoSlot.MaxCount`) этого мода вместо фиксированных 100 шт. Пополнение — когда осталось ¼ лимита |
| More Vaccables (42), Ultimate Vacpack Overhaul (145) и любой другой мод, который патчит `AmmoSlot.MaxCount` | то же: лимит слота задаёт мод вакпака |
| Placement Improvements (179), официальная поддержка в RT | инструмент гаджетов CT ставит через штатный `GadgetItem` (`SetHeldGadget`, `IsPlacementValid`, `IsInLinkedGadgetRange`), поэтому правила и цвета Placement Improvements действуют и для него. Общих хуков нет |
| Better Drones (177), официальная поддержка в RT | общих хуков нет |
| Infinite Health (57) | оба мода отменяют `PlayerModel.LoseHealth`: функция дублирует «Бессмертие», вместе безопасно. CT объявляет это в `CompatibleWith`. Пока Infinite Health включён, урона нет и с выключенным «Бессмертием» |
| Cube Slimes (14), Dynamic HUD (123) | общие методы (`TimeDirector.Update`, `PlayerState.Damage` и `SpendEnergy`): у них только постфиксы, кооперативные хуки CT им не мешают |

Без модов с лимитами вакпака всё по-прежнему: 100 шт., пополнение при 25 и меньше.

Как проверялось: хуки 31 мода с Nexus сверены с хуками CT по исходникам (29 репозиториев GitHub) и IL релизных DLL (17 шт.). Пул из 24 модов (установленные и 17 скачанных) проверен в SR2 Mod Manager: у CT «конфликта хуков» нет ни с одним модом. Оставшийся конфликт в пуле — между чужими модами: Infinite Health ↔ Starlight (оба отменяют `LoseHealth`). Моды без открытых исходников и релизов (например, Infinite Energy, Ultimate Vacpack Overhaul) по коду не проверены; лимиты вакпака у них покрывает общая проверка патчей `AmmoSlot.MaxCount`. В самой игре вместе с этими модами CT пока не запускался.

## Управление
- **Insert** (на ноутбуке — **Fn + Insert**) — открыть или закрыть Creator Toolkit. **Esc** — закрыть меню и отменить неподтверждённое действие.
- Восемь вкладок: Игрок, Спавн, Ресурсы, Мир / погода, Открытия, Съёмка, Карта, Удобство.
- Горизонтальные ползунки и вертикальные полосы прокрутки перетаскиваются **ЛКМ**. Колесо прокручивает каталог; после отпускания бегунка список выравнивается по целым строкам.
- Меню использует собственные IMGUI controls без отсутствующих в игровой IL2CPP-сборке native Slider/TextField/FocusControl. Кнопки, ползунки и скролл читают один native InputSystem pointer; GUI legacy mouse stream не используется для активации кнопок. Native InputDirector переключается в UI-mode и возвращает исходный режим при закрытии. Отдельные глобальные InputAction мод не выключает.

## Новое в 0.5.0: метки, радар и фермерский помощник

Навигация и автоматизация **выключены по умолчанию**. Сам интерфейс — нативный Unity IMGUI, без SDL3, окна другого процесса и сетевого моста. Marine-glass плашки, желейные капсулы и единый процедурный атлас из 16 иконок используют 16 общих UI-текстур; новые панели не создают собственные материалы для игровых объектов.

### Карта → Мои метки

- До **32** точек для каждого сейва, имя до **48** символов и **6** цветов. Можно сохранить проверенную позицию игрока либо поставить свою метку ЛКМ в атласе.
- Имя и цвет редактируются; удаление требует подтверждения. Кнопки «На карте», «Телепорт» и «Маяк / компас» работают с выбранной точкой.
- Хранение: `UserData/CreatorToolkit/waypoints-{GameName}.json`, схема 1, атомарная замена отдельного файла. Это **не изменение `.sav`**; при переходе в другой сейв метки не смешиваются. При повреждённом/неподдерживаемом файле запись блокируется, исходный файл сохраняется.
- Проверенная наземная высота позволяет показать экранный маяк, спроецированный из точки в 3D-мире, и направление на компасе. Обычный 2D-клик задаёт X/Z: для него работает компас, но неизвестная высота маяка не выдумывается. Посадка проверяется при телепорте.
- Навигация обновляется 4 раза/с; плашки расположены ниже штатного названия слайма и его диеты. В меню, на карте, при паузе и чистом кадре они скрыты. Сохранённые точки переживают перезагрузку; активная навигация после смены мира выключается.

### Карта → Радар

- Выберите нативного слайма в каноническом каталоге. Любимая еда берётся из его `SlimeDiet.FavoriteIdents`, а не из предположения по названию. Если любимой еды нет, это явно написано.
- Два независимых режима: любимая еда и редкие материалы. Используются подтверждённые native types `StrangeDiamondCraft`, `SunSapCraft`, `LavaDustCraft`, `PrimordyOilCraft`; названия на экране берутся из игрового каталога.
- Проверяются только **загруженные предметы текущей нативной зоны**, в пределах **100 м**; до **32** ближайших целей. Сканирование 1 раз/с, стрелка и расстояние 4 раза/с.
- Поиск использует существующий `GameModel.identifiablesByIdent`: опрашиваются только нужные типы еды/материалов, без глобального `FindObjectsOfType` и копирования всего реестра акторов. Для каждого совпадения всё равно проверяются загруженный объект, его нативная зона и расстояние. Кэшируются только определения из каталога, не ссылки на акторов.
- Показывается направление к ближайшей подходящей цели. Это не поиск скрытых месторождений через все острова и не обещание обнаружения выгруженных ресурсов. Контурные материалы/дубликаты renderer materials не создаются.

### Карта → Ферма

- Используются только **уже установленные и активные** штатные сборщики плортов и кормушки **загонов**, в пределах **30 м** от игрока. Покупку устройств и постройку загона игрок выполняет обычным способом; production-код сам их не покупает.
- Автосбор запускает native `PlortCollector.StartCollection()`, после чего плорт попадает в штатное хранилище устройства. Произвольные акторы мира не удаляются ради «выдачи» искусственных плортов.
- Кормушки пополняются **из выбранного слота вакпака**, до **4 единиц/с**. Новая еда не создаётся. Проверяются тип, ёмкость и доступность устройства; при отказе/ошибке возвращаются исходные состояния обоих инвентарей.
- Поиск раз в 3 с читает `GameModel.landPlots` и дочерние устройства только у уже загруженных загонов; выгруженные префабы не создаются, глобального Unity object scan нет.
- Нет подходящей еды, кормушка заполнена или устройство далеко → еда не расходуется. Устройства обнаруживаются раз в 3 с; кэши ограничены 64 сборщиками и 64 кормушками. Предметы не переносятся и сбор не запускается в выгруженных регионах, меню или на паузе.
- Включение требует подтверждения: количество еды и плортов сохраняет сама игра. При смене мира автоматизация выключается и ссылки на устройства очищаются.

## Исправления 0.4.x → 0.5.0

- Все **126** названий наград капсул, включая **86** GUID-ссылок на таблицы локализации, разрешаются через нативную локализацию. В описании, подписи и боковой панели нет имён assets или GUID вместо награды; ID самой капсулы остаётся в отдельном техническом футере для точного поиска.
- Проверка сохранённого Waypoint учитывает допустимое безопасное смещение: не более **3 м по горизонтали / 2 м по высоте**. Проверки фактической земли, свободной капсулы игрока и готовности сцены не ослаблены. Для обычных занятых map targets отказ остаётся точным.
- Проверка ammo после стресс-перезагрузок сравнивает **все штатные слоты**, их типы и количества с тем конкретным checkpoint, который игра сохранила непосредственно перед новым процессом, а не с устаревшим значением до нагрузки.
- Native census UI-текстур учитывает и один общий атлас, а не ошибочно ожидает только 11 фоновых текстур.
- Исправлены ожидание готовности popover, сброс выбранного слайма при открытии радара, порядок асинхронного захвата кадров и перекрытия новой навигации/карточек. Тест сборщика использует короткий native ray внутри его реального trigger и отдельно проверяет фактическую доставку плорта в хранилище.

## Удобство

Все новые тумблеры **выключены по умолчанию**, настройки живут только в текущем сеансе. Меню остаётся нативным IMGUI; это не замена игровой UI-библиотеки на SDL3.

- **Исследователь**: бессмертие, бесконечная энергия, скорость ×2, компактный инфо-HUD. Не меняет погоду, квесты или собранные предметы.
- **Кадр**: NoClip, защита, пауза мирового времени и загруженных слаймов, скрытый игровой HUD и вакпак. Меню доступно по Insert. Пауза не останавливает сам интерфейс.
- Повторное нажатие активного профиля или **Восстановить прежние настройки** возвращает точный снимок предыдущих тумблеров и скорости. Переключение профиля сначала отменяет предыдущий. Во время телепорта профиль менять нельзя.
- **SOS**: после включения сохраняет только наземную позицию с проверкой поверхности и свободного места для игрока. **Ctrl + Home** или кнопка возврата используют тот же безопасный native transit, что и карта. Горячая клавиша работает только в обычном gameplay, не во время ввода в меню/карте. Выключение и смена сейва очищают точку.
- **Ближайшая неоткрытая капсула**: обновляет состояния капсул из текущего GameModel, предпочитает текущую локацию и фокусирует обычную карту. Ничего не собирает, не открывает награду и не телепортирует без отдельного действия. Условные теневые награды могут требовать игрового условия появления.
- **Автопополнение выбранного слота**: включается с подтверждением только для открытого непустого совместимого слота. При остатке 1–25 доводит количество до 100 через штатный Count setter. Не заменяет метаданные предмета. Смена выбранного слота, типа ресурса, закрытый/пустой слот или смена сейва отключают чит. Если предметы потрачены до нуля за один кадр, слот не оживляется. Это сохраняемое количество и может превышать обычную ёмкость вакпака.
- **Компактный инфо-HUD**: локализованная зона, XYZ, игровое время, активные эффекты. Положение справа, слева или над нижним игровым HUD. Скрывается при открытом меню/карте, паузе и в режиме чистого кадра. Текст не затемняется вместе с фоном.

## Атлас

1. Открыть **Карта → Открыть всю карту…**, если требуется снять туман и открыть подписи. Это постоянное изменение выбранного сейва — сначала резервная копия.
2. **Открыть атлас** показывает обычную игровую карту с дополнительными метками. Нативные масштаб, перемещение и страницы карты сохраняются.
3. В правой панели выбрать слои. Число на метке означает группу близких точек; щелчок приближает её. Между целями оставляется зазор, подписи зон размещаются вне меток и панели. Метки не занимают заголовок зоны, счётчик капсул и кнопки зума; клики по этим штатным элементам не запускают наш телепорт. Сама метка выбирает объект, а не немедленно телепортирует.
4. Для обычного клика по суше переключить **ЛКМ: обычная метка → ЛКМ: телепорт**. Кнопка **К метке** использует выбранную точку и её высоту.
5. Во время перехода автосохранение приостанавливается, включается временная защита и сохраняются параметры физики игрока. Native SceneLoader подгружает целевую группу; проверяются фактическая CurrentSceneGroup и все destination scene assets. Мотор/гравитация удерживаются до повторяемой готовности земли минимум 0,75 с, затем ещё 0,25 с после установки. Одного ray-hit или изменившегося ID сцены недостаточно. Проверяются уклон, опасные поверхности и свободная капсула игрока. При отсутствии безопасной посадки выполняется возврат; ожидание загрузки ограничено 45 с. Исходные параметры и autosave flag восстанавливаются.
6. **Вернуться** возвращает к позиции до последнего успешного телепорта по карте. Точка привязана к текущему сейву/сеансу.
7. **Поиск / мои метки / настройки** позволяет найти имя или ID, в том числе в незагруженных регионах. Для большого слоя ресурсов лучше задавать конкретный ресурс.

Статический индекс извлечён из текущих игровых bundles, а не скопирован с веб-карты. Он содержит 289 точек разных типов, включая 152 записи обычных капсул/теневых наград; некоторые объекты условные и не обязаны быть одновременно активны. Нативные resource-node data и загруженные капсулы дополняют его во время игры. Индекс используется только при совпадении Addressables catalog hash. После обновления игры неподходящие статические метки отключаются, а не показываются на неверных координатах.

Подписи берутся из нативной локализации зон. Координаты и страницы проецируются средствами нативной карты; высота произвольного клика в 2D не задаёт этаж пещеры. Для конкретного подземного объекта предпочтительнее его метка с исходной высотой.

Незавершённые нативные slime records остаются видимы в каталоге с пометкой «неготовый». Отсутствующий префаб, незарегистрированный native type и текущий сломанный GlitchTarr блокируются **до** регистрации ActorModel и не предлагаются для вакпака. Это не полноценные игровые акторы.

## Радиоактивный и мозаичный: важно

В проверенных shipping-определениях этой версии нет готовых native Rad/Mosaic SlimeDefinition. Записи в **Эксперименты** — **визуальные прототипы на нативной основе Pink**, а не обнаруженные полноценные скрытые слаймы.

- Радиоактивный: зелёный визуальный вариант, без настоящей радиации.
- Мозаичный: отдельные приватные материалы и цветные грани; при недоступном для чтения исходном меше используется штатный BakeMesh для визуального слоя.
- Уникальные диеты, радиация, солнечные осколки, соответствующие плорты и собственное размножение не заявлены.
- Сохранение содержит известного игре базового розового слайма. После перезагрузки специальный внешний вид не сохраняется. Неизвестные ID не регистрируются и не записываются в сейв.
- Экспериментальные записи не предлагаются для заполнения вакпака. Очистка модом распространяется на них только в текущем сеансе владения.

## Безопасность

- Деньги, спавн, ammo, время и разблокировки могут сохраняться игрой. Подтверждение не заменяет резервную копию.
- Gadgets/декорации и дроны, которым нужны специальные модели/станции, не создаются акторным спавнером. Неверные liquid aliases исключены.
- Скорость меняет личную копию CharacterControllerParameters. Нативный `UpdateVelocity(ref Vector3)` не патчится.
- NoClip временно останавливает мотор; при выходе проверяется капсула, возвращаются гравитация, enabled и collision flags даже при ошибке. Работа с каждой возможной скриптовой сценой и чужими модами не гарантируется.
- Очистка не удаляет произвольных пользовательских объектов. После перезапуска/другого сейва tracking не переносится.
- Погода зависит от зарегистрированных состояний конкретной зоны. Недоступные пресеты серые; Clear не удаляет все будущие прогнозы.
- Заморозка слаймов действует только на загруженный мир. Запрет Варров не удаляет уже существующих.
- Полная карта не означает автоматического прохождения квестов, решения всех загадок или получения всех наград.
- Прерывать приложение во время перехода/сохранения не рекомендуется. Выход через локальный relay требует штатного save/flush и не выполняет process kill.


## Стресс-тестирование и границы результата

Точные замеры установленной DLL, сохранность исходных сейвов, повторы загрузки мира и открытые вопросы памяти/FPS записываются в `STRESS-VALIDATION.md` и `VALIDATION.md`. `PASS` тестовой матрицы не означает, что исключена каждая возможная утечка или сертифицированы все будущие игровые сессии.

Дополнительный opt-in `stress.request` в защищённом functional audit включает короткие FPS-окна, burst/refill, реальные переходы сцен и native menu/world reload на собственной копии. Контроль ABBA повторно загружает один проверенный checkpoint без явного пересохранения; byte fingerprint и исходные save-хеши проверяются. Полный процесс ограничен временем; неизвестные/отсутствующие profiler counters отмечаются, а не заменяются вымышленными значениями. Native frame recorders и принудительная сборка памяти работают только в тесте; production GC/quality/Profiler.enabled не меняются.

## Сборка, установка, диагностика

Сборка и проверки: `src/creator/build.ps1`, `test.ps1`. Установка: `release.ps1 -Install`. Pipeline не использует Minecraft и не запускает старый мост.

Установщик требует успешные проверки с SHA-256 именно устанавливаемой DLL; проверяет блокировки, делает резервную копию предыдущей DLL и использует атомарную замену. Старый MinecraftHUD при закрытой игре переносится в `backup/creator-*`, другие моды не меняются. Существующая DLL не перезаписывается при запущенной игре.

`dispatch.ps1 -Rebuild -SelfTest` выполняет штатный save/quit, сборку/проверки/установку и запуск через Steam. При отсутствии native Continue opt-in файл `selftest-save.txt` должен содержать точный GameName и SaveName либо `latest`, разделённые табуляцией; summary и файл валидируются до загрузки. `latest` означает максимальный валидный SaveNumber только указанного GameName после штатного выхода, не случайный последний сейв из других слотов. Проверочный recovery-checkpoint имеет приоритет независимо от наличия кнопки Continue. При opt-in `functional.request` запускается отдельная нативная проверочная копия с checkpoint run/verify/return; хеши исходных `.sav` контролируются на каждом переходе. Копия удаляется только после проверки её принадлежности. Существующий recovery-файл сначала восстанавливается, новый аудит поверх него не запускается.

Диагностика: `UserData/CreatorToolkit/status.txt`, `selftest.txt`, `functional.txt`, `ui-interaction.txt`, `atlas-interaction.txt`, `ui-fonts.txt`. Локальный `cmd.txt`: status, menu, close, catalog, recover, selftest, testplayer, testcancel, quit, capture, atlas, atlasrefresh, atlasreturn, uitest, atlastest. Это локальные opt-in проверки, не сетевой транспорт и не сертификация физического OS-ввода.

Повторный файловый обмен и обнаружение `selftest.request` выполняются фоновым worker с ограниченными очередями; Unity/IL2CPP-вызовы остаются в игровом потоке. Единственное начальное чтение opt-in запроса сохраняет прежнюю загрузку в фоне. Маркер не потребляется обнаружением: штатный старт/отмена самотеста удаляет его и сбрасывает поколение кэша, чтобы запоздавшее чтение не запустило тест повторно и запрос следующего процесса не потерялся при выходе.

Точная проверенная DLL, результаты и ограничения охвата записываются в `VALIDATION.md` и `REPORT-0.5.1.md`; сборка без ошибок сама по себе не подтверждает работоспособность всех игровых действий. Текущие сырые протоколы и отдельные полноразмерные нативные кадры поставляются в `evidence/` и `screenshots/` итогового пакета.

## Готовый пакет и повторная сборка

На игровом компьютере проверенная 0.5.1 уже установлена. Для ручной установки из пакета сначала штатно сохраните и закройте SR2; скопируйте **только** `CreatorToolkit.dll` из `Mods/` в `Mods/` своей игры. Не меняйте DLL у работающего процесса и не копируйте поверх игры весь каталог исходников. Существующие сейвы и JSON-файлы меток не нужно заменять.

Структура исходного проекта для повторной сборки:

```text
project/
  src/creator/                 C# и PowerShell-сценарии из пакета
  refs/                        свои проверенные MelonLoader/IL2CPP/game bindings
  _work/dotnet/dotnet.exe       существующий .NET SDK
```

Мод компилируется для .NET 6, C# 12; тестовый проект — для .NET 8. Сценарии текущего проекта используют SDK из `_work/dotnet` и refs из `refs/`. Игровые DLL, interop assemblies, сам loader, SDK и файлы сохранений **в пакет не включены**. Используйте свои refs именно текущей версии игры; произвольная сборка со старыми bindings не подтверждена этим протоколом. Для другой папки игры измените проверенный target path в install/restart scripts до запуска.

- `release.ps1` — сборка и статические проверки без установки.
- `release.ps1 -Install` — дополнительно защищённая установка после закрытия игры.
- `dispatch.ps1 -BuildOnly` — текущий on-demand task для сборки/проверок без перезапуска игры.
- `dispatch.ps1 -Rebuild -SelfTest` — текущий native pipeline; полная functional/stress-проверка требует явных opt-in маркеров и валидного точного `GameName`, не запускается автоматически при обычной установке.

Сохраняйте резервную копию сейвов самостоятельно перед использованием функций с постоянным эффектом. Сырые протоколы finite-аудита не являются вашими сейвами и не предназначены для загрузки в игру.
